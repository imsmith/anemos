    Anemos.DataModel behaviour (anemos v0.1.0)

    Copy Markdown View Source

    Behaviour for pluggable data format and query engine handlers.

    Implementations register a keyword (e.g., "edn", "xml", "sql") that becomes valid inside data and query block bodies. The runtime delegates parsing, evaluation, and transduction to the registered handler.

    transclude and transduce are not the same word

    They are two halves of one feature and both spellings are deliberate:

    • transclude is the language construct — the optional clause in a data block, transclude to shape(<shape>) with <transducer> as <binding>. It survives as the :transclude field on Anemos.AST.DataDecl and Anemos.CompiledData, and as :transcluded (the computed result) on a Anemos.Runtime.DataStore entry.

    • transduce/3 is the handler operation that carries the clause out. The runtime hands the parsed data plus the clause's shape and transducer to the handler; what comes back is the transcluded value.

    So a data block declares a transclusion, and the handler performs a transduction to satisfy it. Handlers with no transformation support return {:error, :not_supported}.

    Callbacks

    eval(parsed, context)

    Evaluates a parsed value against the dispatch context. Returns {:ok, result} or {:error, :eval_failed}.

    keyword()

    Returns the keyword string identifying this data format (e.g., "edn", "xml").

    parse(raw)

    Parses a raw string body into an internal representation. Returns {:ok, parsed} or {:error, :parse_failed}.

    transduce(data, shape, transducer)

    Transduces data into a new shape. Returns {:ok, result}, {:error, :not_supported}, or {:error, :transduce_failed}.
