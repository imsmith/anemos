# Anemos v0.1.0 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Build a working DSL pipeline: parse `.rule` files into AST, compile to executable Elixir modules, run against an event dispatcher with observable output.

**Architecture:** Elixir/OTP application. NimbleParsec tokenizer + recursive descent parser produces a struct-based AST. Compiler walks the AST and emits supervised GenServer/Broadway-backed rule processes. Event dispatcher routes events to subscribed rules. Module registry provides the `[MODULE::verb]` execution layer. Phoenix.PubSub handles the messaging substrate.

**Tech Stack:** Elixir 1.15+, OTP 26+, NimbleParsec, Phoenix.PubSub, Broadway (later), ExUnit

```elixir
defmodule Anemos.LexerTest do
  use ExUnit.Case, async: true

  alias Anemos.Lexer

  test "tokenizes a minimal rule" do
    input = ~s|rule garage-lights-on { }|
    assert {:ok, tokens} = Lexer.tokenize(input)
    assert [{:keyword, _, :rule}, {:identifier, _, "garage-lights-on"}, {:lbrace, _, _}, {:rbrace, _, _}] = tokens
  end

  test "tokenizes keywords" do
    for kw <- ~w(rule when if at on it let set emit demand condition capability flow context) do
      assert {:ok, [{:keyword, _, ^kw} | _]} = Lexer.tokenize(kw <> " x")
             |> then(fn {:ok, tokens} -> {:ok, Enum.map(tokens, fn {type, meta, val} -> {type, meta, to_string(val)} end)} end)
    end
  end

  test "tokenizes string literals" do
    assert {:ok, tokens} = Lexer.tokenize(~s|"hello world"|)
    assert [{:string, _, "hello world"}] = tokens
  end

  test "tokenizes command expression brackets" do
    assert {:ok, tokens} = Lexer.tokenize(~s|[DEVICE::set "on"]|)
    assert [{:lbracket, _, _}, {:module_id, _, "DEVICE"}, {:double_colon, _, _},
            {:identifier, _, "set"}, {:string, _, "on"}, {:rbracket, _, _}] = tokens
  end

  test "tokenizes sigils" do
    assert {:ok, tokens} = Lexer.tokenize("$myvar @immutable :atom ?query")
    assert [{:mutable_ref, _, "myvar"}, {:immutable_ref, _, "immutable"},
            {:atom, _, "atom"}, {:query_var, _, "query"}] = tokens
  end

  test "tokenizes numbers and durations" do
    assert {:ok, tokens} = Lexer.tokenize("42 3.14 10min 5s")
    assert [{:integer, _, 42}, {:float, _, 3.14},
            {:duration, _, {10, :min}}, {:duration, _, {5, :s}}] = tokens
  end

  test "skips comments" do
    assert {:ok, tokens} = Lexer.tokenize("; this is a comment\nrule x { }")
    assert [{:keyword, _, :rule} | _] = tokens
  end

  test "tracks line numbers" do
    input = "rule x {\n  when Y {\n  }\n}"
    assert {:ok, tokens} = Lexer.tokenize(input)
    {_, meta, _} = Enum.find(tokens, fn {type, _, _} -> type == :keyword end)
    assert meta[:line] == 1
  end
end
```

**Step 2: Run tests, verify they fail**

**Step 3: Implement Lexer with NimbleParsec**

Build `lib/anemos/lexer.ex` using NimbleParsec combinators. Tokenize:
- Keywords (reserved words from spec section 13)
- Identifiers (letters, digits, hyphens, underscores, dots)
- Module IDs (all-caps identifiers)
- String literals (double-quoted)
- Numbers (integer, float, duration with unit suffix, size with unit suffix)
- Sigils (`$ident`, `@ident`, `:ident`, `?ident`)
- Operators (`==`, `!=`, `&&`, `||`, `|>`, `>=`, `<=`, `>`, `<`, `+`, `-`, `*`, `/`, `%`, `!`, `::`)
- Delimiters (`{`, `}`, `[`, `]`, `(`, `)`, `,`)
- Comments (`;` and `#` to end of line)
- Whitespace (skip, but track newlines for line numbers)

The tokenizer returns `{:ok, [{type, metadata, value}]}` or `{:error, message, line, col}`.

**Step 2: Run tests, verify they fail**

**Step 3: Implement parser**

Build `lib/anemos/parser.ex` as a recursive descent parser that consumes the token stream from `Lexer.tokenize/1`:

- `parse/1` — entry point, tokenizes then parses
- `parse_program/1` — consumes declarations until EOF
- `parse_declaration/1` — dispatches on keyword: rule, condition, capability, flow
- `parse_rule/1` — name, `{`, body (trigger blocks + context blocks), `}`
- `parse_context/1` — path, `{`, body, `}`
- `parse_when/1` — event ref, optional `for` duration, optional guard, `{`, statements, `}`
- `parse_if/1` — expression, optional guard, `{`, statements, `}`, optional else
- `parse_statement/1` — dispatches: let, set, emit, demand, log, command, if, etc.
- `parse_command/1` — `[`, MODULE, `::`, verb, args, `]`
- `parse_expression/1` — Pratt parser or precedence climbing for operators

Keep it simple for v0.1.0: support rule, context, when, if, let, set, command, emit, demand, log. Skip: at, on, it, as, with, flow, pipeline, triple patterns (those are post-v0.1.0).

**Step 2: Run tests, verify they fail**

**Step 3: Implement compiler**

The compiler walks the AST and produces `%Anemos.CompiledRule{}` structs:

```elixir
defmodule Anemos.CompiledRule do
  defstruct [:name, :subscriptions, :handler, :meta]
end
```

For v0.1.0, the `handler` is a function that takes `(event_name, context)` and returns `{:ok, [operation]}` where each operation is a map describing what to do. The runtime (Task 7) will execute these operations.

The compiler handles:
- `when` blocks → subscriptions + handler functions
- `if` inside handlers → conditional operation lists
- `let` → variable binding in handler context
- `command` → `%{type: :command, module: m, verb: v, args: a}`
- `emit` → `%{type: :emit, ...}`
- `log` → `%{type: :log, value: v}`

Skip code generation (no `Module.create`). Produce closures instead — simpler, testable, sufficient for v0.1.0.

```elixir
defmodule Mix.Tasks.Anemos.Run do
  use Mix.Task

  @shortdoc "Parse and execute a .rule file"

  def run([file | args]) do
    Mix.Task.run("app.start")
    source = File.read!(file)

    event = extract_event(args)
    case Anemos.run(source, event: event) do
      {:ok, results} ->
        Enum.each(results, fn op -> Mix.shell().info(inspect(op)) end)
      {:error, reason} ->

  end
```
